# ezplm-agents

面向 eZ-PLM 的五个确定性 AI Agent（A1–A5），覆盖「研发工程师 → 采购」的全流程。

核心设计原则只有一条：**建议 → 人确认 → 写库**。这个仓库里没有任何一行代码会自动改动 PLM 里的数据。

## 五个 Agent 与它们的宿主控件

每个 Agent 都寄生在 eZ-PLM 已有的按钮、字段或状态流转上，不新增第 9 个侧边栏菜单。如果某个业务动作在系统里没有宿主控件，说明这个动作本身还不存在——那就应该先补流程，而不是先加 AI。

| ID | 名称 | 宿主控件 | 输出 |
| --- | --- | --- | --- |
| A1 | BOM 体检 | BOM 物料清单页顶部 + 新建版本前置校验 | 18 条规则的问题清单，逐条可采纳/忽略 |
| A2 | 封装与焊盘核对 | 物料详情封装字段 + 替代料对比抽屉 | 焊盘几何一致性 + 未核对项清单（永不结论“可互换”） |
| A3 | 缺料与采购建议 | 生产订单 / 采购申请页 | 需求-可用-缺口三列表 + 采购申请草稿行 |
| A4 | 工程文件导入映射 | 工程文件导入 / 解析的两张映射字典 | 映射候选 + 存量字典错误审计 |
| A5 | 物料建档与选型 | 新建物料对话框 + 搜索系统库 + 全局搜索 | 属性模板预填 + 候选排序打分 |

## 三条不可协商的红线

1. **永不自动落库。** `Suggestion` 类型上写死了 `autoApplyForbidden: true`，所有写入必须经过 diff 预览 + 人工确认 + 可撤销 + 审计留痕。
2. **没有证据不许渲染。** `assertRenderable()` 会拒绝 `evidence` 为空的建议。用户被坑一次就再也不看这个面板了。
3. **不许替人做决定。** 发邮件、下单、改权限这三件事只能由人来做，Agent 最多起草。

## 置信度决定交互形态

| 置信度 | 交互 | 含义 |
| --- | --- | --- |
| high | 幽灵预填（灰字默认填好，一键撤销） | 两条独立证据链一致 |
| medium | 展开候选，人必须点一个 | 有 ≥2 个候选或证据冲突 |
| low | 只标记，不给答案 | 只能提示存在风险 |

## 目录结构

    src/core/            契约与五个纯函数底座（无副作用，可单测）
    src/agents/a1..a5/   五个 Agent 的确定性内核
    src/adapters/ezplm/  唯一需要你们工程师改的地方
    test/                fixture 全部取自真实 BOM 数据
    docs/                接入说明（先读 03）

## 工程师从哪里开始

1. 读 `docs/03-mount-points.md`，确认五个挂载点在你们代码里对应哪个组件。
2. 实现 `src/adapters/ezplm/client.ts` 里的 `EzplmClient` 接口，其余代码不需要改。
3. 读 `docs/02-backend-prereqs.md`。有三个后端字段是阻塞项，缺了其中任何一个，对应规则会自动降级为不启用而不是乱报。
4. 按 `docs/04-rollout.md` 的五期节奏灰度。第一期只上 7 条零歧义规则，目的是让用户的第一印象是“它说的都对”。

## 关于这个公开仓库的脱敏

仓库是公开的，所以代码里不含具体的 workspace 标识、项目/BOM 的 UUID 和内部接口路径，这些位置统一用占位符（形如 `<WORKSPACE>`、`<BOM_ID>`、`<API_BASE>`），在 `src/adapters/ezplm/client.ts` 里集中配置。

测试 fixture 里保留了真实的物料型号与规格描述串（如 0603WAF1004T5E、SLH0704S220MTT），这些是公开的元器件型号，不属于内部信息，但它们是这套解析器唯一可靠的验证依据，去掉就没法证明代码是对的。
