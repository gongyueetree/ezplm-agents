# 接入契约

五个 Agent 的输出全部收敛到一个结构：`Suggestion`。宿主 UI 只需要认识它一个。新增 Agent 不允许新增出口类型，否则前端会长出五套互不相通的渲染逻辑，半年后没人敢动。

## 置信度就是交互形态

置信度不是一个供参考的数字，它直接决定界面长什么样。这一层映射写在 `confidenceToInteraction()` 里，前端不要自己发明。

high 对应幽灵预填：灰字、默认填好、一键撤销。只有两条独立证据链指向同一个值时才允许（见 `crossValidate`）。同一来源重复两遍不算两条，那只是同一个错误被读了两次。

medium 对应展开候选，人必须点一个，且候选至少两个。单个候选的 medium 在类型层面就会被 `assertRenderable` 拦下来。

low 只标记，不给答案。给了答案的 low 同样会被拦。

## 没有证据不许渲染

`evidence` 为空的建议禁止上屏。这不是防御性编程，是产品红线——用户被坑一次之后就不会再看这个面板，之后做得再准也没用。

前端的正确做法是把整个列表交给 `filterRenderable()`，只渲染 `ok`，把 `dropped` 上报到内部监控。dropped 不是数据问题，是 Agent 自己的 bug。

每条 `evidence.ref` 必须能跳转到具体位置。统一格式由 `ref.bomLine() / ref.part() / ref.dictEntry()` 生成，不要手拼。

## assumed 必须展示

`assumed` 里装的是推导过程中做过的假设，比如“裸数字按位号前缀 C 解释为 pF”。这种假设大多数时候是对的，但错的时候错得很难查。不展示它等于把“我猜的”包装成“我知道的”。

## 三个字段级的硬要求

`target.field` 必须指到字段，才能做 diff 预览。整对象级的建议无法被安全地一键接受。

`target.version` 必须带上。不带版本的建议会在换版之后飘到新数据上，变成一条无人能解释的幽灵提示。

`autoApplyForbidden: true` 是类型层面的锁。没有任何合法路径可以把它设为 false。如果哪天有人要求“高置信就自动应用吧”，请拿这行代码去拒绍他。自动应用省的是几秒钟，赔的是整个系统的可信度。

## 审计

接受、拒绝、修改、撤销四种动作全部要记。拒绝也要记——拒绝率高的规则应该被下线，而这件事只有审计数据能告诉你。

`evidenceSnapshot` 必须存快照。证据源会变，几个月后复盘“当时为什么接受了这个建议”时，重新去读一遍数据源是没有意义的。

审计表只提供 append，不提供 delete。`AuditSink` 接口里根本没有删除方法，这是故意的。

## 价格的四层责任

`PriceSource` 四个取值从高到低：真实采购单价、系统库参考现货价、同族插值、模型估价。`decidePrice()` 保证层级低的永不覆盖层级高的。

两条额外的硬规则：¥0 一律当作未知而不是 0 元；推算值必须在界面上与真实值一眼能分开。现有「AI 智能估价」用标红表示“暂无估价信息”的思路是对的，要延续。

## 字段来源标记

`FieldOrigin` 是三个后端前置改造里最容易被忽略的一个，但它的后果最难查。

现有的「批量同步系统库字段」会提示“同步后本地数据将被覆盖”，并提供“仅同步未修改的字段”。如果 A5 接受的写入没有被当作“已修改”，一次全量同步就会静默抹掉它们，而且没有任何提示。用户只会发现“上星期填的东西没了”，然后不再信任整套功能。

在 `fieldOrigin` 开关为 false 时，A5 会主动抛出一条 block 级建议（`A5.SYNC_RISK`）提醒这一点。这是故意的，不要把它屏蔽掉。
