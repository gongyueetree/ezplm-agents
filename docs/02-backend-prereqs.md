# 后端前置改造

这四项是阻塞项。缺了其中任何一个,对应规则会自动降级为不启用(`FeatureFlags` 控制),而不是拿空值硬算然后乱报。乱报一次,用户就再也不信这个面板了。

优先级按下面的顺序,不建议调换。

---

## 一、BOM 行「采购属性」枚举 —— 最紧急

**字段:** `bom_line.purchase_type`,枚举值:采购 / 虚拟 / 自制 / 客供 / 不装。

**为什么它排第一:** 现在系统里没有这个字段,于是 TestPoint、LOGO、M3 螺丝孔、装配说明这类行永远填不完型号和价格,永远留在"待处理"计数里。一个永远归不了零的计数器,用户学会的第一件事就是忽略它。

这不是一个"顺便加个字段"的事——它决定了 A1 的核心交互(计数徽标)能不能成立。

**默认值:** 采购。历史数据不要自动推断,让用户在体检面板里逐条确认更安全。代码里的 `isNonPurchase()` 目前用位号前缀做了兜底(TP/MH/LOGO/FID/NP/MK),但这只是权宜之计。

**影响规则:** R05、R12、R13、R17,以及 A3 的整个缺料计算。

---

## 二、物料生命周期状态

**字段:** `part.lifecycle`。现有枚举只有 正常 / 禁用,不足以支撑生命周期判断。

**建议枚举:** 量产 / 新料 / 不推荐新设计(NRND) / 停产(EOL) / 停售 / 禁用。

**数据来源:** 母公司做元器件数据(苏州芯查查),云端元件库有 110 万+ 条,参数对比与替代料推荐都有。生命周期字段大概率能从那边同步过来,不需要人工维护——这一点值得先去确认,如果能同步,这项的成本会比想象的低很多。

**影响规则:** A1/R16,以及 A5 选型打分里的硬门槛(停产料直接不进候选)。

---

## 三、参考价格表

**表结构:** (物料, 供应商, 量档, 单价, 币种, 报价日期, 来源)。来源字段对应 `PriceSource` 四个枚举值。

**为什么需要独立成表:** 现在价格是物料上的一个单值,导致四种完全不同性质的价格挤在同一个字段里:真实采购价、系统库现货参考价、同族插值、模型估价。一旦挤在一起,就没法回答"这个成本汇总能不能拿去对外报价"。

**顺带要做的一件小事:** 把存量的 `¥0` 清成 `null`,并且禁止写 0。0 与未知不是一回事,0 会让成本汇总看起来是正确的。

**影响规则:** A1/R13,A5 的 `decidePrice()`。

---

## 四、字段级来源标记

**字段:** 每个可被 Agent 写入的字段增加 `origin`,枚举 `system_sync | ai_suggested_accepted | manual`。

**为什么这一项最容易被忽略、后果最难查:** 现有「批量同步系统库字段」明确提示"同步后本地数据将被覆盖",并且提供"仅同步未修改的字段"这个选项。如果 A5 接受的写入没有被标记成"已修改",那么一次全量同步就会静默抹掉用户接受过的全部建议,没有任何提示。

用户只会发现"上星期填的东西不见了",然后停止使用整套功能。而这个 bug 从日志上几乎查不出来。

**要求:** `ai_suggested_accepted` 必须与 `manual` 同等地被当作"已修改"。

**影响:** A5 的所有写入路径。在这项就绪前,A5 会持续抛出 `A5.SYNC_RISK`(block 级)。

---

## 五、审计表(不算阻塞,但要一起做)

`AuditRecord` 的字段直接建表即可。两条硬约束:只提供 append,不提供 delete;`evidence_snapshot` 存 JSON 快照而不是外键引用。

外键引用的问题是证据源会变——三个月后回来复盘"当时为什么接受了这条建议",重新读一遍已经变了的数据源是没有意义的。

---

## 六、两个可选但很有用的接口

库存与在途查询(`getInventory` / `getInTransit`)是 A3 的前提。没有它们,A3 只能算需求量,算不出缺口。

属性名列表(`getAttributeNames`)用于 A5 的属性名治理。存量属性库里有一百多个扁平属性名且没有绑分类,命名也不统一(中英混用、带不带单位、带不带方括号全都有)。`auditAttributeNames()` 会输出需要人工裁决的清单。

注意一个约束:现有系统"仅专业版支持自定义属性名称"。所以模板里的 canonical 名优先复用存量属性名,`aliases` 只用于归一读取。**不要反过来批量改存量属性名**——那是一次不可逆的全库改造,收益远小于风险。
